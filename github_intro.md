# GitHub Introduction

# What is GitHub?

**GitHub** is a cloud-based platform that helps developers store, manage, share, and collaborate on software projects using Git.

It is one of the world's largest platforms for software development and open-source collaboration.

---

## Why GitHub?

- Store code online
- Collaborate with teams
- Track project history
- Review code changes
- Manage software projects
- Automate development workflows
- Showcase your portfolio
- Contribute to Open Source

# Creating a Repository

Click

```
New Repository
```

Fill in:

- Repository Name
- Description
- Public / Private
- Add README
- Add .gitignore
- Add License

Click

```
Create Repository
```

# README.md

The README is the first page users see.

A good README contains:

- Project Name
- Description
- Features
- Installation
- Usage
- Screenshots
- Technologies Used
- Contributors
- License

---

# Example README

```markdown
# Student Management System

A simple web application to manage student records.

## Features

- Add Students
- Update Students
- Delete Students
- Search Students

## Technologies

- HTML
- CSS
- JavaScript

## Installation

Clone the repository and open index.html
```

# Forks

Forking creates your own copy of someone else's repository.

```
Original Repository

        ↓

      Fork

        ↓

 Your Repository
```

You can make changes without affecting the original project.

# Branches

A branch allows independent development.

Example

```
main

├── feature-login

├── feature-payment

└── bugfix-navbar
```

Each feature is developed separately.

---

# Pull Requests

A Pull Request (PR) is a request to merge code into another branch.

Workflow

```
Create Branch

↓

Develop Feature

↓

Push Changes

↓

Open Pull Request

↓

Review

↓

Merge
```

---

# Pull Request Components

A Pull Request contains

- Title
- Description
- Files Changed
- Comments
- Review Status

Example

```
Title

Add Login Feature

Description

Added Login Page
Added Validation
Updated Documentation
```

---

# Code Review

Before merging, reviewers check

- Code Quality
- Readability
- Naming
- Security
- Performance
- Bugs

Example Comments

```
Please rename this variable.

Good implementation.

Can you simplify this function?

Add validation here.
```

---

# Merge

Once approved, the Pull Request is merged into the main branch.

```
feature-login

        ↓

      Merge

        ↓

       main
```
